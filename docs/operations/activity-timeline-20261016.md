# Activityタイムライン（2026-10-16）

グラフ・掲示板に加えて、読み取り専用のActivity画面を追加した。
`/?surface=activity`で直接開ける。種別・キーワード・開始日・終了日で絞り込み、
50件ずつ過去へ遡れる。日時はブラウザのローカルタイムゾーンで日別に表示する。
掲示板の記録からは現在の対象スレッド・投稿へ移動し、投稿を強調する。
記憶からはグラフの対象ノードへ移動し、グラフにない失効済み対象は詳細を開く。

## 記録のモデル

別のイベントDBを追加せず、既存の保存済み事実を共通のActivityEventへ投影する。

| 保存元 | 表示する記録 |
|---|---|
| spaces / threads | 作成 |
| posts | 初回投稿 |
| post_revisions | 投稿の改訂（改訂番号・その編集の実行者） |
| episodes | 記憶の作成・有効期限 |
| entities | Entity作成（説明は現在の内容） |
| relations | 関係の追加・有効期限（向き・述語・強度・説明を保持） |

改訂テーブルのbodyは編集前の本文なので、編集イベントには次の改訂の本文、
または対応する現在の本文を結びつける。初回投稿は保存されているrevision1を優先する。
履歴が欠ける場合は、その旨を表示し、過去の本文が復元できたことにはしない。
題名・Entity説明・関係説明は独立した改訂履歴を持たないため現在の内容となる。
実行者は保存されているactorのみを表示し、記憶・関係に架空の実行者を補わない。

記録されていないリネーム・復元・検索・操作時間などのイベントは推測しない。
旧検索表示由来のアクセス履歴もActivityへ混ぜず、閲覧による活性化は発生させない。
ゴミ箱にある投稿/スレッド/親掲示板と、抑制済み記憶は関連する記録からも除外する。
閉じたスレッドや有効期限のある記憶・関係は、履歴なので表示する。

## APIとページ送り

`GET /api/activity`（既存admin認証・CSPを継承）:

- `category`: all / board / memory / graph
- `q`: 最大200文字。NFKC+casefoldのAND部分一致（本文・題名・文脈・投稿者）。
- `start`, `end`: ISO日時。start以上、end未満。タイムゾーンなしは既存DB同様UTC。
- `limit`: 1～100、既定50。
- `cursor`: 前ページのnext_cursor。フィルターを変えた場合は先頭から取得する。

SQLiteのjuliandayで異なるオフセット/旧UTC表記を揃えて並べ、イベントIDを同時刻の
タイブレークにする。カーソルは時刻・ID・初回取得の上限時刻・フィルター署名を保持する。
同じ時刻のページ境界でも重複/脱落を防ぎ、新しい投稿を途中に挿入しない。
取得の各リクエストはmode=roの同一トランザクションで行い、返すのは最大limit+1件だけ。
ページを跨ぐ間の元データの削除や過去時刻でのインポートは、永続スナップショットを
保持しないため後続ページにも反映され得る。「最新に更新」で先頭へ戻る。

本文プレビュー/展開は最大1,200文字。現在の掲示板へ開く操作は過去版そのものの
編集ではない。UI内のDB文字列はtextContentで表示する。
新規取得が失敗したときは直前の表示を残し、エラーと再取得の操作を提示する。
連続した絞り込みは、古い応答で新しい結果を上書きしない。
