# グラフ表示の修復（2026-10-16）

## 原因と変更

本番の `/api/graph?scope=active` は175ノード・0エッジを返していた。
DBには360本の現役関係があり、画面用変換がepisode→entityとentity→entityしか
扱わなかったため、episode間や掲示板への関係が全て捨てられていた。
その結果、力学配置も接続を利用できず、画面は格子状の点の一覧になっていた。
日本語ラベルの折り返し、フィルター後の配置、詳細パネル開閉時の寸法変更にも問題があった。

`admin/graph_view.py` はepisode・entity・thread・postの有向関係を同じモデルで投影する。
relation ID、述語、強度、説明、source/targetの向きを保持し、仮の関係は生成しない。
掲示板ノードは保存済み関係の端点だけを取得し、無関係な全投稿を描画しない。
activeでは無効関係・無効ノードを除外し、欠損端点・未対応型は描画しない。
ゴミ箱にある投稿、スレッド、親掲示板の内容は全scopeで除外する。
旧DBとゴミ箱拡張済みDBの双方を扱い、読み取り専用SQLite接続の同一トランザクションで取得する。

`static/graph-view.js` は投影、本文検索、方向付き近傍探索を同じGraphModelで処理する。
力学配置・有向階層・円形配置、述語選択、入出方向、1～3ホップ、近傍のみ表示、
全体へ戻る、再配置、画面に収める操作を用意した。
全体表示では縮小時のラベル重複を抑え、接続の多いノードを入口にする。
検索はNFKC正規化した本文全体へのAND部分一致で、意味検索とは別の画面内絞り込みである。
日本語は空白がなくても部分一致し、描画ラベルはanywhereで折り返す。
ノード・エッジを選ぶと、方向付き接続一覧から記憶や出典投稿を辿れる。
履歴や活性化を更新するmemory_exploreは呼ばない。

依存追加・スキーマ移行・再埋め込みは不要。既存APIのフィールドを維持して
search_text、relation_id、descriptionと掲示板ノード型を追加した。

## 制限

ブラウザ検証はローカル管理UI経路で実施する。公開側の認証フローは変更しない。
全体表示は大きなグラフを縮小するため、本文を読むには検索・ノード選択・ズームを使う。
現状規模での検証であり、数万ノード向けのページング/描画上限は別途必要。
thread/postは保存済み関係のあるものを表示し、全掲示板を自動的な包含辺で埋めない。
